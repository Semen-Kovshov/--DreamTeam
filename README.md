# Вторая сторона — тренажёр переговоров

Кейс ЛЦТ 2026. Интерактивный симулятор деловых переговоров: игрок ведёт
**свободный диалог** с виртуальным оппонентом, и исход зависит от стратегии —
какие вопросы задавал, чем аргументировал, когда и как уступал.

Внутри — не дерево диалогов и не «чат с ботом», а **детерминированное
переговорное ядро**: реплика игрока распознаётся в структурированные ходы
(открытый вопрос, аргумент по интересу, условная уступка, ультиматум, …),
правила меняют состояние оппонента (доверие, напряжение, аппетит, терпение),
тактика оппонента выбирается деревом решений, и только озвучка — за LLM.
Поэтому каждый балл разбора прослеживается до конкретной реплики, а симулятор
полностью работает и без модели (эвристики + шаблоны).

Методики из постановки кейса встроены как механики, а не как справка:
Гарвардский метод (интересы/рычаги, объективные критерии, пакетные размены до
Парето), SPIN (типы вопросов ускоряют раскрытие интересов), BATNA/ZOPA (итог
меряется положением в зоне возможного соглашения) —
см. [`docs/03-methodology.md`](docs/03-methodology.md).

## Статус

🟢 Рабочий прототип: партии с живой локальной моделью пройдены от каталога до
разбора во всех сценариях, 104 теста бэкенда и 7 тестов интерфейса зелёные,
офлайн-режим проверен отключением LLM. Каждый сценарий имеет в тестах полную
скриптовую партию: сильная линия закрывается сделкой в ZOPA, давление на
мягкую персону приводит к тихому разрыву.

По формальному ТЗ «Арена переговоров» добавлен **контур администратора**:
экран «Админ» задаёт контекст симуляции (сфера, тема, роли, тон собеседника,
сложность, пожелания) и генерирует по нему полный сценарий через LLM;
черновик можно править в JSON-редакторе с проверкой схемы и сохранить —
сценарий сразу появляется в каталоге игрока без перезапуска. Экран партии
адаптирован под **мобильный сценарий** (приоритет ТЗ): на узком экране боковые
панели складываются в верхнюю полосу с мини-индикаторами и вкладками
Журнал/Бриф/Советы.

Интерфейс собран по дизайн-системе **«хвоя»** (комплект дизайнера в
`design/handoff-hvoya/`: токены, спецификация, эталоны-макеты; шрифты
IBM Plex Sans/Mono лежат в бандле — интернет не нужен). Партия подаётся как
**лайт-новелла** с полным артом: 4 нарисованные сцены, персонажи со сменой
эмоций (4 спрайта на каждого: спокоен → доволен → напряжён → на взводе),
печатающиеся реплики, журнал и бриф — оверлеями. Промпты, по которым
генерировался арт, — в [`docs/07-art-prompts.md`](docs/07-art-prompts.md). Помимо слов есть **действия-мелочи** (налить воды, записать в
блокнот, взглянуть в телефон, выдержать паузу, посмотреть на часы, пододвинуть
кофе) — детерминированные жесты с эффектами по персоне: телефон обижает
мягкого и впечатляет жёсткого, тишина давит на того, кто только что назвал
условия. В среднем режиме **считается время ответа**: пауза дольше 75 секунд
читается как колебание, дольше 150 — жжёт терпение; глоток воды легально
«покупает» раздумье. Все ассеты сцены подключаются дизайнером без кода —
контракт в [`docs/06-ui-spec.md`](docs/06-ui-spec.md).

## Стек

**Backend:** Python 3.11 · FastAPI · pydantic · httpx
**LLM:** любой OpenAI-совместимый endpoint из `.env`; локально — Ollama
(`qwen3:4b-instruct`), офлайн-режим без модели для тестов и страховки на защите
**Frontend:** React 18 · TypeScript · Vite · Tailwind
**Без Docker** — всё поднимается локально.

## Запуск для жюри

Нужны **Python 3.11+** и **Node 18+** (Node — только на время сборки
интерфейса). Зависимости зафиксированы в `backend/requirements.txt` и
`frontend/package-lock.json`; интернет нужен один раз — скачать пакеты.

Окружение (один раз):

```bash
py -3.11 -m venv backend/.venv && backend/.venv/Scripts/python.exe -m pip install -r backend/requirements.txt
```

```bash
npm install --prefix frontend && npm run build --prefix frontend
```

Запуск (интерфейс и API на одном порту):

```bash
backend/.venv/Scripts/python.exe -m uvicorn app.main:app --port 8030 --app-dir backend
```

Открыть **http://localhost:8030** — каталог сценариев; кнопка «Админ» в шапке —
контур администратора. Без настройки LLM всё работает в офлайн-режиме
(эвристики + шаблоны), партию можно пройти целиком; строка статуса модели
видна в `/api/health`. Чтобы подключить модель — раздел «LLM» ниже.

Для разработки — dev-сервер с горячей перезагрузкой (прокси в бэкенд):

```bash
npm run dev --prefix frontend -- --port 5176
```

Тесты:

```bash
backend/.venv/Scripts/python.exe -m pytest backend/tests -c backend/pytest.ini --rootdir=backend
```

```bash
npm test --prefix frontend
```

## LLM

Настройка — [`.env`](.env.example): `NEGO_LLM_BASE_URL`, `NEGO_LLM_MODEL`,
`NEGO_LLM_API_KEY`. Локальная модель через Ollama работает без интернета;
когда организаторы дадут свой API — заменить три значения, код не трогать.
Если endpoint недоступен, тренажёр не падает: распознавание ходов берут
эвристики, реплики оппонента — шаблоны сценария (помечается в `/api/health`).

Модель 4B заставила прописать честность отдельно, и это стало фичей:

- разметке модели не доверяются факты — числа, условность «если…, то…»,
  вопросная форма и тон всегда сверяются с эвристиками (`app/nlu/pipeline.py`);
- в репликах оппонента числа проверяются по белому списку из намерения;
  выдуманное число = повтор, затем шаблон, причина пишется в журнал хода;
- реплики раскрытия интересов всегда авторские: это ключевые моменты партии,
  и модель их перевирала («три месяца» → «месяц»);
- `trust_env=False` в HTTP-клиенте: системный прокси (V2Ray) перехватывал
  запросы к localhost и отвечал 503 с пустым телом.
