# Соответствие ТЗ «Арена переговоров»

## Глава 2. Описание задачи

| Требование | Реализация |
|---|---|
| Практика в безопасной среде, многократные попытки | Партию можно переигрывать без ограничений; журнал игр (`/api/history`) копит попытки |
| Исход зависит от стратегии, формулировок, аргументов | Свободный текстовый ввод → NLU в структурированные ходы → детерминированные правила эффектов; см. [`02-architecture.md`](02-architecture.md), [`03-methodology.md`](03-methodology.md) |
| Настройка контекста под ситуации и аудитории | Контур администратора: генерация сценария по контексту + JSON-редактор (`/api/admin`, экран «Админ») |
| Обратная связь по итогам | Разбор: счёт, компетенции, ключевые моменты, рекомендации, стенограмма с причинами каждого эффекта |
| **2.2 Конфигурируемость (обязательно)** | Админ задаёт сферу, тему, роли, тон (персона: мягкий/позиционный/жёсткий), сложность 1–4, единицы и рамки торга, пожелания — по ним LLM генерирует полный сценарий, детерминированные допроверки чинят экономику, результат сразу в каталоге |
| **2.3 Интерфейс администратора (обязательно)** | Экран «Админ»: форма контекста, генерация с прогрессом, предупреждения об автоправках, список сценариев (встроенные защищены), JSON-редактор с валидацией и предпросмотром карточки |
| 2.4 Геймификация (опц.) | Лайт-новелла с артом и сменой эмоций персонажа, действия-мелочи, события-повороты, таймер раздумий, очки и разбор после раунда |
| 2.5 UX/UI (опц.) | Дизайн-система «хвоя» по комплекту дизайнера, мобильная вёрстка партии |

## Глава 3. Программно-аппаратные требования

| Требование | Реализация |
|---|---|
| Жюри запускает без нестандартного железа | Web-приложение; локальный запуск: venv + `uvicorn`, один процесс на 8030 |
| Приоритет мобильного сценария | Экран партии адаптивен: на узком экране боковые панели складываются в полосу с мини-индикаторами и вкладками Журнал/Бриф/Советы |
| Демо не ломается после перезапуска | Партии переживают рестарт (`data/sessions/*.json`), сценарии и журнал — файлы |
| AI/LLM допустим; ключи через переменные окружения | OpenAI-совместимый endpoint из `.env` (`NEGO_LLM_*`), локально Ollama; см. `.env.example` |
| Запасной режим без платных API | Полный офлайн-режим: эвристики распознавания + шаблонные реплики; партия проходится целиком без модели |
| Инструкция локального запуска, зафиксированные зависимости | README «Запуск для жюри»; `backend/requirements.txt`, `frontend/package-lock.json` |

[`05-demo-script.md`](05-demo-script.md).

## Глава 8. Критерии оценки

| Критерий | Чем закрыт |
|---|---|
| 8.2 Прототип с ключевой механикой | Рабочий прототип: каталог → бриф → партия → разбор; 104+7 тестов |
| 8.2 Конфигурируемость: настройки админа влияют на сценарий | Сгенерированный сценарий сохраняется в каталог без перезапуска и сразу играется |
| 8.3 Контуры пользователя и администратора | Оба реализованы в одном интерфейсе (кнопка «Админ») |
| 8.3 Сценарии с ветвлением | 4 встроенных сценария: развилки от тактик оппонента, событий-поворотов и пакетных разменов; финалы — сделка в ZOPA / компромисс / разрыв / тихий уход |
| 8.4 Исход зависит от стратегии и формулировок | Детерминированное ядро: каждый эффект с причиной, разбор прослеживается до реплик |
| 8.4 Понятная обратная связь | Компетенции с объяснениями, моменты партии, рекомендации, аннотированная стенограмма |
