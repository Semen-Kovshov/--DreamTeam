# Сценарий защиты

Хронометраж на 7 минут. Перед защитой: `ollama serve` запущен, модель
`qwen3:4b-instruct` прогрета одним запросом; бэкенд поднят
(`uvicorn app.main:app --port 8030 --app-dir backend`), интерфейс собран.
Страховка: если LLM недоступна — тренажёр сам переходит на эвристики и
авторские реплики, ничего перезапускать не нужно (виден бейдж в шапке).

## 1. Проблема (30 сек)

Переговорам учат по книгам, а навык — поведенческий: пока не потренируешься,
не научишься. Тренироваться на живых сделках дорого. Показываем тренажёр, где
можно безопасно ошибаться и **видеть цену каждой ошибки**.

## 2. В чём идея (1 мин)

Не дерево диалогов и не «чат с ботом». Реплика игрока свободная; она
распознаётся в переговорные приёмы, приёмы бьют по детерминированной модели
оппонента (доверие, напряжение, аппетит, скрытые интересы), тактику выбирает
движок, и только слова оппонента подбирает LLM. Поэтому:

- исход зависит от стратегии и формулировок, а не от кубика;
- каждый балл разбора прослеживается до конкретной реплики;
- работает офлайн — модель заменяется правкой `.env`.

Методики кейса встроены как механики: SPIN-вопросы вскрывают интересы,
гарвардские «объективные критерии» бьют сильнее «хочу», сделка меряется
против BATNA и ZOPA, быстрые уступки повышают аппетит оппонента.

## 3. Демо (4 мин) — сценарий «Разговор о повышении», режим «Обучение»

1. **Каталог**: четыре сценария, три персоны (мягкая, позиционная, жёсткая).
   Открыть бриф: цель, BATNA, факты — тренажёр учит готовиться. Партия — в
   подаче лайт-новеллы: сцена, персонаж, настроение которого видно.
2. **Плохой ход** (показать цену ошибки): написать «Или 200 — или я ухожу».
   Индикатор напряжения прыгает, в фишках — «Ультиматум», Ирина жёстко
   отвечает, настроение персонажа темнеет. Тут же показать **действие**:
   пододвинуть кофе или налить воды — жест гасит накал без слов. Упомянуть:
   в среднем режиме считается и время ответа — затянул пауза, оппонент видит
   колебание.
3. **Правильная линия** (по подсказкам): открытый вопрос про финдира →
   Ирина раскрывает скрытый интерес; аргумент «стоимость замены перед
   релизом» → в фишках «Аргумент», позиция двигается; условное предложение
   «если пересмотр через полгода — готов на 188» → встречное предложение
   растёт на глазах.
4. **Закрытие**: принять финальное предложение кнопкой.
5. **Разбор** — главный экран: счёт и грейд, пять компетенций с объяснением,
   шкала ZOPA («сколько взяли из возможного»), «осталось на столе» с
   конкретным лучшим пакетом, ключевые моменты, рекомендации с готовыми
   формулировками, стенограмма, где у каждого эффекта написана причина,
   а у каждой реплики оппонента — «почему так».
6. **Контур администратора** (по ТЗ демо включает настройку контекста):
   кнопка «Админ» → форма контекста (сфера, тема, роли, тон, сложность,
   рамки торга, пожелания). Генерация на локальной 4B — минуты, поэтому
   показываем **заранее сгенерированный** черновик (лежит готовым в
   [`demo/crm-srok-draft.json`](demo/crm-srok-draft.json), автоправки того
   прогона — в `demo/warnings.txt`): список автоправок
   («что генератор починил за модель»), правка пары строк в редакторе →
   Сохранить → сценарий уже в каталоге игрока, открыть его бриф. Тезис:
   настройки администратора реально порождают игровой сценарий, а не файл
   «на потом».

## 4. Под капотом (1 мин)

- Сценарий — JSON: интересы, рычаги, персона, события. Новый кейс —
  новый файл, код не трогается.
- LLM только на входе и выходе; числа в её репликах проверяются по белому
  списку, реплики раскрытия — авторские. Модель локальная (Ollama, 4B),
  замена на API организаторов — три строки в `.env`.
- 104 автотеста на бэкенд (+7 на интерфейс): правила, уступки, ZOPA/Парето,
  распознавание, полные партии, генератор сценариев. Партия детерминирована
  и воспроизводима.

## 5. Вариативность и планы (30 сек)

Режимы «обучение / свободный / экзамен» (в экзамене индикаторы скрыты),
события посреди партии, журнал тренировок с динамикой, мобильная вёрстка
партии. Дальше — голосовой ввод, командные турниры, библиотеки сценариев
для T&D-отделов поверх готового генератора.

## Вопросы, которых ждём

| Вопрос | Ответ |
|---|---|
| Чем это лучше промпта в ChatGPT? | Промпт не гарантирует ни честного исхода, ни объяснимого разбора: у нас исход считает движок, LLM только говорит. И это проверено тестами |
| Что если игрок пишет ерунду? | Ход «не по теме»: оппонент возвращает к делу, терпение тратится, партия честно заканчивается «время вышло» |
| Почему маленькая модель? | Демо без интернета и чужих ключей; архитектура не зависит от размера — endpoint меняется в `.env` |
| Как добавить сценарий? | Через админку: форма контекста → генерация черновика → правка в редакторе → сохранить. Или JSON-файл в `data/scenarios` руками — валидация подскажет, чего не хватает |
| Генерация — это же LLM, ей можно верить? | Черновик проходит детерминированные допроверки (экономика торга, ссылки, ZOPA) и ту же pydantic-схему, что встроенные сценарии; каждая автоправка показана админу. Сломать движок сгенерированным сценарием нельзя |
