# Архитектура

## Слои

```
реплика игрока
   │
   ▼
NLU: ход + числа           app/nlu       LLM (JSON-схема) → эвристики
   │
   ▼
Ядро: правила эффектов     app/engine    детерминированное, журнал причин
   │   состояние оппонента: доверие, напряжение, аппетит, терпение,
   │   раскрытые интересы, предложения сторон
   ▼
Тактика оппонента          app/engine    дерево решений от состояния и персоны
   │   намерение: counter_offer(178) / hold_firm / accept / warn / …
   ▼
Озвучка                    app/engine    LLM в голосе персоны → шаблоны
   │   числа проверяются по белому списку намерения
   ▼
реплика оппонента + дельты индикаторов + журнал эффектов
```

Сценарий — данные (`data/scenarios/*.json`), валидируются pydantic-моделью.
Ядро не знает ни одного сценария по имени: интересы, рычаги, вопросы торга,
персона, события, палитра сцены — всё из файла. Новый сценарий = новый JSON.
Контент действий-мелочей (подписи, ремарки, реплики персон, лимиты) — тоже
данные: `data/actions.json`; в коде только эффекты жестов. Во фронтенде
предметных данных нет — всё приходит из API.

## Модули бэкенда

| Модуль | Ответственность |
|---|---|
| `app/scenarios` | Модель сценария, загрузчик, валидация |
| `app/nlu` | Классификация реплики в ходы: `llm_classify` + `heuristics`, объединение |
| `app/engine/moves` | Таксономия ходов, полезная нагрузка (числа предложения, рычаг) |
| `app/engine/rules` | Эффекты ходов на состояние; каждый эффект — с текстом причины |
| `app/engine/npc` | Выбор тактики оппонента, логика уступок и принятия |
| `app/engine/phrasing` | Озвучка тактики: LLM + проверка чисел + шаблонный запасной путь |
| `app/engine/outcome` | Утилиты сторон, ZOPA, Парето-граница, итог сделки |
| `app/engine/debrief` | Компетенции, ключевые моменты, рекомендации |
| `app/engine/session` | Состояние партии, применение хода, стенограмма с аннотациями |
| `app/llm` | Провайдеры: OpenAI-совместимый endpoint (Ollama/API организаторов), stub |
| `app/scenarios/generate` | Генерация сценария по контексту админа: LLM-черновик + детерминированные допроверки |
| `app/api` | HTTP: сценарии, сессии, ходы, подсказки, разбор, журнал; `admin` — контур администратора |

## API

| Метод | Путь | Что делает |
|---|---|---|
| GET | `/api/health` | Живость + статус LLM (провайдер, модель, доступность) |
| GET | `/api/scenarios` | Каталог: карточки без скрытых полей |
| POST | `/api/sessions` | Старт: `{scenario_id, mode}` → бриф + вступительная реплика |
| POST | `/api/sessions/{id}/turns` | Ход игрока: `{text}` → ходы, эффекты, реплика оппонента, настроение, индикаторы, статус |
| POST | `/api/sessions/{id}/actions` | Действие-мелочь: `{action_id}` → ремарка, реакция, эффекты (кулдауны и лимиты — на сервере) |
| GET | `/api/sessions/{id}/hints` | Три подсказки-техники под текущее состояние |
| POST | `/api/sessions/{id}/finish` | Досрочно завершить (принять предложение / выйти) |
| GET | `/api/sessions/{id}/debrief` | Разбор: счёт, компетенции, моменты, стенограмма |
| GET | `/api/history` | Журнал завершённых игр (файл `data/history.jsonl`) |

Скрытое состояние (аппетит, интересы, пределы) наружу не отдаётся до разбора —
фронтенд не может «подсмотреть». В режиме экзамена скрыты и индикаторы.

### Контур администратора (`/api/admin`)

По ТЗ администратор задаёт контекст симуляции — сфера, тема, роли, тон
(персона), сложность — и этот контекст определяет сценарий:

| Метод | Путь | Что делает |
|---|---|---|
| GET | `/api/admin/scenarios` | Список с пометкой встроенных |
| POST | `/api/admin/scenarios/generate` | Контекст → черновик сценария + список автоправок |
| POST | `/api/admin/scenarios/validate` | Проверка JSON по схеме, карточка для предпросмотра |
| POST | `/api/admin/scenarios` | Сохранить (`overwrite` для перезаписи); каталог перечитывается сразу |
| DELETE | `/api/admin/scenarios/{id}` | Удалить (встроенные защищены) |

Генерация (`app/scenarios/generate.py`) — два вызова LLM со строгими
JSON-схемами (экономика+ядро, затем шаблоны реплик), после которых
детерминированные допроверки чинят типовые ошибки модели и записывают каждую
правку в список предупреждений админу: направление торга выводится из чисел
игрока, старт/предел оппонента переставляются при инверсии, при пустой ZOPA
предел сдвигается, ссылки рычагов на интересы перепривязываются, дубликаты id
опций переименовываются, в шаблоны с офертой дописывается `{offer}`. Итог
проходит ту же pydantic-валидацию, что и встроенные сценарии, — сгенерированное
не может сломать движок. На локальной 4B-модели полный сценарий пишется
несколько минут, поэтому у генерации свой HTTP-клиент с большим таймаутом.

## Режимы

| Режим | Подсказки | Индикаторы | Кому |
|---|---|---|---|
| `training` | три техники на выбор + свой текст | видны | первое знакомство |
| `free` | нет | видны | основной |
| `exam` | нет | скрыты до разбора | зачёт |

## LLM

Конфиг в `.env` (`NEGO_LLM_*`), протокол OpenAI Chat Completions — локальная
Ollama и API организаторов взаимозаменяемы правкой трёх строк. Два вызова на
ход, оба короткие: классификация (строгая JSON-схема) и озвучка (свободный
текст с проверкой чисел). Без модели работают эвристики и шаблоны — тесты и
офлайн-демо.

Разметке модели не доверяются факты: слияние в `nlu/pipeline.py` берёт из
эвристик числа предложения, условность, вопросную форму, тон и BATNA;
галлюцинированные ходы этих типов отбрасываются. Реплики раскрытия интересов
всегда авторские (модель искажала факты пересказом), в остальных числа
проверяются по белому списку намерения; причина каждого фолбэка — в журнале
хода (`voice_note`).
